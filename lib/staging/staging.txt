Live (default): URL has no `staging=1` (or has `staging=0` / `staging=false`). No `html.staging`, no link rewriting. **Non-official** preview builds: a top-left **Live** badge (`#staging-enter-button`) opens staging (`?staging=1`); with **`npm run dev:api`** running, **frame** and **gallery layout** still load from SQLite on live (same API as staging) while gallery **interaction** uses published `localStorage` keys only. **Official** canonical deploy: **`data-official-live="true"`** or **`1`** on `<html>` (each page), or site-wide **`localStorage.customdev_official_live`** — live URLs get **`html.official-live`**, **no Live badge**, no gallery testing chrome. **`?staging=1` still opens staging** (toolbar **Official site** checkbox toggles the localStorage override). Legacy `localStorage` key `customdev_staging` is cleared on every live load.

Staging: URL must include **`?staging=1`** (or `#staging=1` in the hash). Then `staging.js` adds `html.staging`, a top-left **Staging** badge (`#staging-mode-label`), and appends `?staging=1` to same-origin HTML links so navigation stays in staging. **`body`** gets **`padding-top: var(--staging-status-bar-height)`** so the whole page sits **below** the fixed **`#staging-status-bar`**; the same variable (measured from the bar + updated on resize) positions **`#staging-site-structure-panel`** under the bar. **Click “Staging”** to **reload without staging** (live): the `staging` query param is removed (and stripped from a `hash` query string when present). To the right of the badge (same top bar, `#staging-status-bar`), **Publish** (`#staging-publish`) flushes gallery testing panels to `sessionStorage`, saves dirty **frame** (all unsaved cells) and **gallery layout** rows to SQLite via the layout API, copies every `.draggable-gallery` session JSON to `localStorage` `customdev_gallery_prefs_published_<id>`, then **reloads without `staging` in the URL** (same as clicking **Staging**). Requires **`npm run dev:api`**; shows an error if the API is unreachable or SQLite save fails. **For** pages with **`data-site-frame-page`** (e.g. `index.html`) get a **dotted frame** and a **`pageName / {label}`** label on the frame root ( **`label`** comes from SQLite **`frame.label`**, defaulting to the word **frame** when empty); **`js/web-dev-base/staging-gui-settings.js`** builds that chrome (invoked from **`site-frame.js`**). Single-click the label toggles the floating frame panel (`#staging-frame-panel-…`) to edit **`frame` / `frame_cell`**: **Frame (SQLite)** panel: **top strip** (cols, rows, grid gap %, label, layout typography) + **click a cell on the page** or **All cells** list + single cell editor. **Cell padding** is **% of the mount** (uniform or **Edit sides** for four %; stored as JSON like grid gap). When set, it **overrides** page/slot padding on that cell (homepage `.column-slot` / `.projects` defaults are suppressed for that mount). Text **inner padding** is not edited in the panel (existing DB values are preserved on save). While the panel is open, **all cell edits preview on the page**; frame default typography live-updates **text cells still on layout defaults** only. The staging frame chip shows **• unsaved** when the panel differs from SQLite. **Save** PATCHes the frame and the **selected** cell (panel open). **Publish** saves the frame and **every** dirty cell draft when the panel has unsaved changes. **Close** reloads last saved from the API and reverts unsaved preview; close is **blocked** if `GET /api/frame` fails. **Frame (SQLite)** grid gap: **Up / Right / Down / Left** as **% of the frame** (stored JSON on `frame.grid_gap`; live preview while the panel is open). Per-cell editors use the Figma-style font row, **Use layout typography**, **Use page font**; **Add text** seeds from layout typography. **Text** cells use ordered **content blocks** (text segments + inline links) stored as JSON in **`frame_cell_text.body_blocks`** (`bodyBlocks` in the API); legacy single footer **`nav_url`** / **`nav_label`** rows are migrated on read. **Image** cells store a path **relative to `assets/`** (e.g. `images/tomato.png` or `images/FarewellMrFuji/foo.png`); staging **`GET /api/asset-images`** recursively lists **all image files under `assets/images/`** (every subfolder); flat dropdown, manual path, **(none)**, **Refresh list**; Save requires the file on disk; live **`img.src`** is `assets/…` or `../assets/…` with URL-encoded path segments (spaces in folder/file names). **Image** cells expose **fit** (`object-fit`), **alignment** (`object-position` presets), **scale (%)** (25–250, default 100, `transform` + `transform-origin`), optional **max width** (stored in **`frame_cell_image`**; PATCH **`imageStyle`** with **`objectFit`**, **`objectAlign`**, **`scalePct`**, **`maxWidth`**). **Drag the panel header** to reposition (**`sessionStorage`** **`customdev_staging_frame_panel_pos_<pageSlug>`**). **`#staging-structure-toggle`** (**Pages / frames / galleries**) opens a dialog (`#staging-site-structure-panel`) that reads and writes **`lib/db/customdev.db`** via the **local layout API** (`GET /api/registry` returns **pages**, **galleries**, and **frames**; `POST`/`PATCH`/`DELETE` page and gallery; **`POST /api/frame`** creates a frame when a page has none). **Add page**, **Add gallery**, and **Add frame** are collapsible (`<details>`, closed by default). The **Frames** list is read-only (edit cells on the page). Registry lists have **Edit** per row for pages and galleries (`PATCH` page name/header/footer or gallery fields including **`galleryKey`** rename—must stay unique per page). After renaming a gallery key in SQLite, update **`data-gallery-key`** / **`createDraggableGallery({ galleryKey })`** on the page so **`GET /api/layout`** matches. Run **`npm run dev:api`** (Python `server/dev_api.py`, default `http://127.0.0.1:8787`) while editing structure; override base URL with `window.__CUSTOMDEV_LAYOUT_API__` or `<meta name="customdev-layout-api" content="http://127.0.0.1:8787">`. **Download registry JSON** exports **pages**, **galleries**, and **frames**. `window` fires `customdev-staging-site-structure-changed` with `detail.pages` / `detail.galleries` / **`detail.frames`** when the registry changes.

**Frame vs gallery:** **`mountSiteFramePage`** + **`frame` / `frame_cell`** hold arbitrary **HTML** or **image URLs** in a configurable grid (`[data-frame-cell-index]` mounts). **`createDraggableGallery`** is the **strip + zoom “media gallery”** — keep it for navigable **image / video-style** sequences (e.g. project pages), not for replacing the marketing column grid.

Draggable galleries (`createDraggableGallery` in `js/web-dev-base/gallery-core/gallery-core.js`): when `html.staging` and `stagingGalleryToolbar` is not `false`, the gallery root gets a **dotted border** and a **visible label** showing **`pageName / galleryKey`** on that gallery (not the site staging badge). **Double-click** the label (second click of a double-click) to **inline-rename** the SQLite **`galleryKey`** via **`PATCH /api/gallery`** when a layout row exists (`data-gallery-registry-id` from **`GET /api/layout`**). Single-click still toggles the testing panel. The label toggles a **floating, draggable panel** for **that gallery only** (drag by the panel header; **×** closes). When not **`official-live`**, **`GET /api/layout`** (same API base as above) loads **layout** (thumbnail strip / zoom flags, column grid, zoom_style → zoom image transition, style tokens, optional font row) before the gallery DOM is built when the API is reachable — on staging and on preview **live**. In staging, the panel has **Layout (SQLite)** vs **Interaction** sections. **Interaction** prefs persist per gallery id in `sessionStorage` JSON `customdev_staging_gallery_prefs_<id>` (`stripNav`, strip thumbnail gestures, `scroll`, `zoomOpenAnim`, `stripClosedAlign`, and `slideTransition` only when no DB gallery row locks layout). On **live** (`!html.staging`) the gallery reads **only** published `localStorage` `customdev_gallery_prefs_published_<id>` for interaction prefs. Use **`staging.js`** **Publish** to copy session interaction prefs to published keys and reload live. Panel position uses `customdev_staging_testing_panel_pos_<id>`. **Production checklist:** The top-left **Live** label is **`#staging-enter-button`** from **`lib/staging/staging.js`**, not from **`project-page.js`**. It appears on **every** page that loads `staging.js` **without** an official flag. Mark **each** such HTML file for the canonical deploy: **`data-official-live="true"`** on `<html>` (see `index.html`, `pages/*.html`) or **`<meta name="customdev-official-live" content="true">`**. For **local staging work**, use a branch or copies **without** that attribute, or remove it temporarily. **Alternative (cleanest for prod):** build **two artifacts** — production output **omits** `staging.js` (and `staging.css`) entirely; preview/staging builds include them.

**If `?staging=1` does nothing** and you see **no** Staging / Publish / **Pages / galleries** bar: the page has **`data-official-live="true"`** (or meta) — staging is disabled on that document. Use **`false`** or remove the attribute for preview, or open **`index.html`** / **`pages/gallery.html`** with staging enabled.

**Official live is per HTML file** (`<html data-official-live="true">` or `false`). Toggling it on `index.html` does **not** change `pages/farewell-mr-fuji.html` — each page that loads `staging.js` needs its own attribute for production deploy.

**Site-wide official (local dev):** Open **`?staging=1`** (works even when HTML says official). Use the toolbar checkbox **Official site** — sets `localStorage.customdev_official_live` to `1` or `0` and reloads; overrides every page until cleared (`localStorage.removeItem('customdev_official_live')`). When official: no **Live** badge on live URLs; gallery testing chrome stays off. **`?staging=1` still opens staging** for editing. Values: `true` / `1` / `yes` / empty attribute = official; `false` / `0` / `no` = preview with **Live** badge.
