Live (default): URL has no `staging=1` (or has `staging=0` / `staging=false`). No `html.staging`, no link rewriting. A top-left **Live** badge (`#staging-enter-button`, `lib/staging/staging.css`) shows the current mode; **click** reloads the **same page with `?staging=1`** to open staging preview. Legacy `localStorage` key `customdev_staging` is cleared on every live load.

Staging: URL must include **`?staging=1`** (or `#staging=1` in the hash). Then `staging.js` adds `html.staging`, a top-left **Staging** badge (`#staging-mode-label`), and appends `?staging=1` to same-origin HTML links so navigation stays in staging. **Click “Staging”** to **reload without staging** (live): the `staging` query param is removed (and stripped from a `hash` query string when present).

Draggable galleries (`createDraggableGallery` in `js/web-dev-base/gallery-core/gallery-core.js`): when `html.staging` and `stagingGalleryToolbar` is not `false`, the gallery root gets a **dotted border** and a **“Gallery testing”** label **on that gallery** (not the site staging badge). The label toggles a **floating, draggable panel** for **that gallery only** (drag by the panel header; **×** closes). While staging, options persist per gallery id in `sessionStorage` JSON `customdev_staging_gallery_prefs_<id>` (`stripNav`, `stripClickAction`, `stripDblclickAction`, `stripContextmenuAction`, `scroll`, `zoomOpenAnim`, `slideTransition`; legacy `openZoomClick` / `openZoomDblclick` / `openZoomContextmenu`, JSON `activate`, and flat keys `customdev_staging_gallery_nav`, `customdev_staging_gallery_activate`, `customdev_staging_gallery_scroll` are read if JSON is missing; if session JSON is missing, the panel can seed from **published** `localStorage` `customdev_gallery_prefs_published_<id>`). **Save & publish to live** in the panel copies the current session JSON into `customdev_gallery_prefs_published_<id>`; on **live** (`!html.staging`) the gallery reads **only** that published key (not staging session), so unpublished tweaks do not affect live. Panel position uses `customdev_staging_testing_panel_pos_<id>`. Changes dispatch `window` event `customdev-staging-gallery-settings` with `detail.galleryStorageId` so only that instance updates. Styles: `lib/staging/staging.css`.

Farewell, Mr. Fuji (`pages/farewell-mr-fuji.html`): when staging is on **and** the viewport matches the site mobile breakpoint (`max-width: 900px`, same as `main.css`), `farewell-mr-fuji.js` calls `forceLandscape()` so `html` gains `project-page-force-landscape` and mobile CSS can tighten vertical chrome for landscape-style layouts (preview shells or phones).

Staging URLs (GitHub Pages for this repo): **`https://nymx22.github.io/customWebDev/?staging=1`** — append `?staging=1` to any path on that origin (e.g. `…/pages/farewell-mr-fuji.html?staging=1`). For local previews, use the same query on `http://127.0.0.1:<port>/…`.

Column grids for homepage and contact are always in `lib/layout/layout.css` at laptop widths (not gated by staging).

Valid URL shape: **`scheme` + `host` + `/` + path** — not `http://pages/…` (that treats `pages` as the hostname). Examples: `http://127.0.0.1:5500/pages/farewell-mr-fuji.html?staging=1` (local server) or `https://nymx22.github.io/customWebDev/pages/farewell-mr-fuji.html?staging=1` (GitHub Pages).
