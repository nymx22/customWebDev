Live (default): URL has no `staging=1` (or has `staging=0` / `staging=false`). No `html.staging`, no link rewriting. **Non-official** builds: a top-left **Live** badge (`#staging-enter-button`) opens staging preview (`?staging=1`). **Official** canonical deploy: **`data-official-live="true"`** or **`1`** on `<html>` (see `index.html`), or `<meta name="customdev-official-live" content="true">` / `1` — then **`?staging=1` is ignored**, `<html>` gets class **`official-live`**, and **staging.js adds no UI** (no Live control, no status strip, no staging/testing affordances from this script). Legacy `localStorage` key `customdev_staging` is cleared on every live load.

Staging: URL must include **`?staging=1`** (or `#staging=1` in the hash). Then `staging.js` adds `html.staging`, a top-left **Staging** badge (`#staging-mode-label`), and appends `?staging=1` to same-origin HTML links so navigation stays in staging. **Click “Staging”** to **reload without staging** (live): the `staging` query param is removed (and stripped from a `hash` query string when present). To the right of the badge (same top bar, `#staging-status-bar`), **Publish galleries to live** (`#staging-gallery-publish`) dispatches `customdev-staging-gallery-sync-session-prefs` so each gallery testing panel flushes into `sessionStorage`, then copies every `.draggable-gallery` session JSON to `localStorage` `customdev_gallery_prefs_published_<id>` and fires `customdev-staging-gallery-settings` per id. **Pages / galleries** (`#staging-structure-toggle`) opens a dialog (`#staging-site-structure-panel`) that reads and writes **`lib/db/customdev.db`** via the **local layout API** (`GET /api/registry`, `POST`/`DELETE` page and gallery). Run **`npm run dev:api`** (Python `server/dev_api.py`, default `http://127.0.0.1:8787`) while editing structure; override base URL with `window.__CUSTOMDEV_LAYOUT_API__` or `<meta name="customdev-layout-api" content="http://127.0.0.1:8787">`. **Download registry JSON** exports the current registry snapshot. `window` fires `customdev-staging-site-structure-changed` with `detail.pages` / `detail.galleries` when the registry changes.

Draggable galleries (`createDraggableGallery` in `js/web-dev-base/gallery-core/gallery-core.js`): when `html.staging` and `stagingGalleryToolbar` is not `false`, the gallery root gets a **dotted border** and a **“Gallery testing”** label **on that gallery** (not the site staging badge). The label toggles a **floating, draggable panel** for **that gallery only** (drag by the panel header; **×** closes). In staging, **`GET /api/layout`** (same API base as above) loads **layout** (thumbnail strip / zoom flags, column grid, zoom_style → zoom image transition, style tokens, optional font row) before the gallery DOM is built when the API is reachable; the panel has **Layout (SQLite)** vs **Interaction** sections. **Interaction** prefs persist per gallery id in `sessionStorage` JSON `customdev_staging_gallery_prefs_<id>` (`stripNav`, strip thumbnail gestures, `scroll`, `zoomOpenAnim`, `stripClosedAlign`, and `slideTransition` only when no DB gallery row locks layout). On **live** (`!html.staging`) the gallery reads **only** published `localStorage` `customdev_gallery_prefs_published_<id>` for interaction prefs. Use **`staging.js`** **Publish galleries to live** to copy session interaction prefs to published keys. Panel position uses `customdev_staging_testing_panel_pos_<id>`. Changes dispatch `window` event `customdev-staging-gallery-settings` with `detail.galleryStorageId` so only that instance updates. Styles: `lib/staging/staging.css`.

Farewell, Mr. Fuji (`pages/farewell-mr-fuji.html`): when staging is on **and** the viewport matches the site mobile breakpoint (`max-width: 900px`, same as `main.css`), `farewell-mr-fuji.js` calls `forceLandscape()` so `html` gains `project-page-force-landscape` and mobile CSS can tighten vertical chrome for landscape-style layouts (preview shells or phones).

Staging URLs (GitHub Pages for this repo): **`https://nymx22.github.io/customWebDev/?staging=1`** — append `?staging=1` to any path on that origin (e.g. `…/pages/farewell-mr-fuji.html?staging=1`). For local previews, use the same query on `http://127.0.0.1:<port>/…` and run **`npm run dev:api`** so layout and the Pages / galleries dialog can reach SQLite.

Column grids for homepage and contact are always in `lib/layout/layout.css` at laptop widths (not gated by staging).

Valid URL shape: **`scheme` + `host` + `/` + path** — not `http://pages/…` (that treats `pages` as the hostname). Examples: `http://127.0.0.1:5500/pages/farewell-mr-fuji.html?staging=1` (local server) or `https://nymx22.github.io/customWebDev/pages/farewell-mr-fuji.html?staging=1` (GitHub Pages).

**Production checklist:** The top-left **Live** label is **`#staging-enter-button`** from **`lib/staging/staging.js`**, not from **`project-page.js`**. It appears on **every** page that loads `staging.js` **without** an official flag. Mark **each** such HTML file for the canonical deploy: **`data-official-live="true"`** on `<html>` (see `index.html`, `pages/*.html`) or **`<meta name="customdev-official-live" content="true">`**. For **local staging work**, use a branch or copies **without** that attribute, or remove it temporarily. **Alternative (cleanest for prod):** build **two artifacts** — production output **omits** `staging.js` (and `staging.css`) entirely; preview/staging builds include them.
